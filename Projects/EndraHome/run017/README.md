# EndraHome Run017 — built-in Files (new hardware test pending)

Home Files slot (index 3) will use an in-app read-only Documents browser when no external file manager .tns is assigned. Folder navigation is based on the working Run014 app-assignment picker but it lists all regular file types. Enter on a file shows information (name, path and size); supported text extensions have a read-only bounded 4-KiB scrolling preview. Unsupported JPG/PNG/PDF show information only: viewer not yet installed. Existing external app override, native QWERTY rename, transactional config, fast hardware exit and return-home preserved. The original app-assignment picker remains .tns-only. Do not overwrite `EndraHome_Apps.cfg.tns`. Keep previously tested Run014–016 binaries available.

## mViewer source examined
The supplied `mviewer.zip` contains actual source for **mViewer CX Edition 4.1** (2013) and standalone `mviewer_cx.tns`. Its readme documents JPEG/BMP/PNG support, progressive zoom, panning, and contrast adjustment. Source includes `mviewer_cx/source/readjpeg.c` with bundled libjpeg, `source/mviewer.c` with zoom controls, `source/screen.c` and other modules. Its old standalone file browser `browse.c`, TSR/startup hooks, original LCD takeover, and compatibility-mode packaging must NOT be copied into EndraHome. Future image viewing should retain EndraHome's own native Files interface, port ONLY decoding + zoom/pan logic, and keep fast no-refresh hardware cleanup. GPLv2 source license requires distributing corresponding GPLv2-compliant source and notices for any copied/derived code. Source ZIP currently resides in this conversation, not the repo.

**Run017 is intentionally read-only and does not yet render JPEGs.** Next image milestone should test baseline/progressive JPEG feasibility, strict memory/dimensions and zoom at 320x240 using the existing safe framebuffer before a device upload. Do not claim every JPEG works before hardware tests.
